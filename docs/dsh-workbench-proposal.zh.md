# DSH Studio 实现方案

[English](dsh-workbench-proposal.md) | 中文

## 1. 产品与技术基础

DSH Studio 是基于 DeepSeek Harness 源码定制的桌面 Agent 软件，支持对话、项目开发、工具执行、模型接入、Agent Teams 和云端记忆。

- 软件名称：DSH Studio。
- 仓库名称：`dsh-studio`。
- 命令行：`dsh`。
- 运行平台：Intel macOS、Apple Silicon macOS、Windows。
- 桌面框架：沿用 DSH 的 Electron 桌面与 Web UI。
- 执行运行时：沿用 DSH 的 Agent 执行循环、文件工具、终端工具、审批、取消和会话机制。
- 扩展方式：通过 DSH 插件和内部接口实现定制功能。
- 源码管理：固定上游提交，保留定制改动与上游更新的追踪记录。

## 2. 模块划分

| 模块 | 实现内容 |
| --- | --- |
| 桌面应用 | 项目、对话、工具执行、审批、任务进度、文件与改动查看 |
| 认证 | Codex、Antigravity 浏览器登录、凭据保存、续期、退出 |
| 模型接入 | 模型目录、模型选择、流式请求、工具调用、错误处理 |
| Agent Teams | 官方 Lead、teammates、成员消息、任务板与任务依赖 |
| 云端记忆 | 会话记录、共享记忆、任务上下文与检索 |
| 同步与恢复 | 本地缓存、事件同步、设备目录绑定、团队与会话恢复 |
| 管理端 | 数据检索、设备管理、存储配置、备份恢复与运行日志 |

桌面负责本地开发执行，云端负责数据持久化、同步和恢复。

## 3. 认证与模型接入

### 3.1 Codex 与 Antigravity

在 DSH 内部增加对应的认证适配和模型适配。

认证流程：点击登录 → 打开系统浏览器 → 完成授权 → 接收回调 → 保存凭据 → 获取模型列表 → 选择模型。

认证功能包括：

- 登录、取消登录、退出登录和重新授权。
- 展示登录状态、凭据有效状态及失败原因。
- 自动刷新凭据，对并发刷新进行合并。
- 重启后恢复认证状态和模型选择。
- 各来源独立保存配置，切换来源后恢复对应设置。
- macOS Keychain / Windows Credential Manager 保存敏感凭据。

模型适配功能包括：

- 获取并缓存可用模型列表。
- 携带对应授权发起模型请求。
- 将上游响应转换为 DSH 的模型事件。
- 支持文本流、工具调用、工具结果、多轮执行和取消。
- 输出明确的授权、限额、网络及协议错误。

浏览器授权与协议适配参考 CLIProxyAPI 实现，在 DSH 的认证及模型接口中完成开发。

### 3.2 自定义 API

沿用 DSH 的 Chat Completions、Responses、Anthropic Messages 接入能力。

提供 Base URL、API Key、协议、模型列表获取、手动添加模型和连接测试。保存模型列表与当前选择，后台刷新目录。

## 4. Agent Teams

使用 DSH 官方 Agent Teams。

- Lead 创建和管理 teammates。
- 成员通过官方消息机制协作。
- 使用官方任务板进行分派、认领、依赖管理和完成登记。
- 团队和任务状态由官方持久事件生成。
- 成果文档、改动说明及验证结果关联到对应任务和会话。
- Lead 检查成果后完成任务，或通过成员消息要求补充。
- 桌面展示成员状态、任务进展、消息和关联成果。

同一团队由一个本地运行时执行，共用工作目录。Lead 协调成员可能重叠的文件修改，桌面展示官方文件范围警告。

## 5. 云端记忆

### 5.1 数据内容

| 数据 | 保存内容 |
| --- | --- |
| 会话记录 | 用户消息、模型输出、工具调用与结果、执行状态 |
| 项目记忆 | 目标、约束、决定、已验证事实和关联代码版本 |
| 工作上下文 | 进度、尝试、阻塞、待办和验证依据 |
| 团队记录 | 官方成员、任务、依赖和关联消息的持久事件 |
| 交付材料 | 成果说明、文档引用、附件及检查记录 |

记忆记录包含来源、时间、关联项目、任务、会话和代码版本。支持修订、废弃和历史查看。

### 5.2 使用与检索

- 采用结构化索引与全文搜索。
- 按当前项目、任务和会话检索相关记忆。
- 将相关内容加入模型上下文。
- 从记忆记录定位原始会话和验证依据。
- 对会话、工具结果和日志中的敏感凭据进行脱敏。

## 6. 同步与跨设备恢复

### 6.1 同步

通过 DSH 的持久化接口和会话生命周期扩展实现同步。

- 本地保存会话日志和同步队列。
- 事件使用稳定 ID、顺序号和幂等提交。
- 断网时暂存，恢复连接后重试。
- 展示待同步、同步中、已同步和失败状态。
- 云端项目使用稳定 ID，各设备独立绑定本地目录。
- 成果文档保存可访问引用及代码版本，或上传为附件。

### 6.2 恢复流程

1. 停止当前设备上的团队执行。
2. 将会话、团队事件和记忆同步到云端。
3. 在另一设备打开对应项目并绑定本地目录。
4. 核对 Git 版本和开发环境。
5. 恢复会话与团队状态，加载相关工作上下文。
6. 继续执行未完成任务。

使用同步版本和设备接管机制保证同一团队的单实例执行。恢复过程保留已完成工具调用的结果，待执行操作由新运行实例处理。代码版本发生变化时提示核对关联记忆。恢复失败时保留原始数据并显示具体原因。

## 7. 服务端与 Web 管理台

服务端采用 TypeScript、Node.js、SQLite WAL 和全文索引，通过 Docker 部署。会话事件按批次、稳定序号和事务写入。附件支持服务端目录和 S3 兼容对象存储。

服务启动时提供 Web 管理台。管理密钥支持首次生成和环境配置，桌面设备凭据支持撤销。

管理台功能：

- 项目、会话和团队记录查询。
- 官方任务状态及成果查看。
- 共享记忆搜索、编辑和历史追溯。
- 设备、同步状态和接管状态管理。
- 同步失败、模型调用失败及运行日志诊断。
- 存储用量、保留策略和 S3 配置。
- 数据备份、恢复和完整性检查。

## 8. 桌面交互

沿用 DSH 的项目与对话界面，统一模型认证、工具执行、审批和任务状态展示。Agent Teams 提供成员、任务和消息视图，支持切换成员会话查看工作进展。

### 弹窗

- Esc 关闭最上层弹窗、菜单或浮层。
- 编辑内容未保存时确认是否放弃。
- 关闭进度窗口后任务继续执行。
- 取消任务使用明确的取消操作。

### 快捷键

| 快捷键 | 操作 |
| --- | --- |
| Cmd/Ctrl+K | 搜索与操作面板 |
| Cmd/Ctrl+S | 保存当前编辑内容 |
| Cmd/Ctrl+Enter | 提交或确认 |
| Tab / Shift+Tab | 切换焦点 |
| 方向键 / Enter | 列表、菜单及选择操作 |
| Esc | 关闭最上层界面 |

快捷键支持查看和调整，遵循终端、输入法及编辑器的输入优先级。

## 9. 实施阶段

1. 固定 DSH 源码基线，验证各平台构建、插件接口、工具执行和持久化。
2. 完成 Codex、Antigravity 内部认证及模型适配，完善自定义 API 配置。
3. 接入官方 Agent Teams，完成团队界面与成果关联。
4. 实现云端记忆、事件同步、设备绑定和恢复。
5. 完成管理台、Esc、快捷键、日志、安装和更新。

## 10. 验收标准

- macOS 与 Windows 安装后可运行，命令行 `dsh` 可用。
- Codex、Antigravity 登录、退出、刷新和重启恢复正常。
- 各模型来源支持流式输出、文件工具、命令执行、多轮调用和取消。
- 官方 Agent Teams 完成 Lead 与两个 teammate 的分派、消息和任务执行。
- 云端记忆可检索、修订，并可追溯原始依据。
- macOS 与 Windows 之间恢复会话及团队后，可以继续未完成工作。
- 断网重试保持事件和交付数据一致。
- 所有应用弹窗支持 Esc，快捷键可通过键盘完成对应操作。
- 管理台可查看记录、诊断失败、管理存储并完成备份恢复。

## 11. 本轮改进的剩余实施计划

本节记录 2026-10-15 本轮改进的后续范围与验收依据；第 9 节是产品总体路线，不代表本轮待办。按真实账号验证、阶段 4、阶段 5 的顺序推进，阶段 5 再按目录、Skills/MCP、Hooks 分批交付。云端记忆、跨设备同步和管理台仍属于总体路线，本轮不新增这些开发任务。

### 11.1 已完成范围与保留约束

- 阶段 1：模型用量归一化与统计展示已提交，包括 Gemini 思考 token、缓存字段缺失与明确为零的区分，以及单轮和会话统计的共同处理；真实账号覆盖仍按下一节补齐。
- 阶段 2：Gemini/Antigravity 模型目录缓存、并发请求合并和后台刷新已提交；真实账号的切换耗时仍待实测。
- 阶段 3：新建对话默认普通模式，对话内通过 `/team` 单向开启团队模式；开启后使用官方团队能力，既有会话保持原有行为。详见[升级说明](upgrade-guide/v0.2.1-alpha.3/session-team-activation/guide.zh.md)。
- 上游合并、图标和 DSH Studio 品牌替换已经完成，桌面打包验收已通过；后续计划不重复这些工作，也不安排安装包构建或打包验收。
- 后续工作保持官方团队角色、提示词、工具与协作机制，不增加团队能力重写或普通/团队双向切换。

### 11.2 优先补齐：真实账号用量与切换验证

问题依据：DeepSeek 官方账号登录时，底部有会话总 token，但回复下方缺少单轮用量；GPT 两处均显示。原始账号事件尚未取得，因此不能把共用统计修复视为该截图问题已经验证解决。

- [ ] 分别使用 GPT、内置 DeepSeek 官方账号和 Gemini/Antigravity 复现单轮、多轮、工具调用、取消与重试，记录实际协议和模型来源。
- [ ] 采集脱敏的 usage 字段、归一化结果、请求/步骤/轮次关联，以及单轮统计未被采用的具体原因；采样不包含凭据或对话正文。
- [ ] 对照 GPT Responses 的 `usage`、DeepSeek 实际登录链路的用量事件，以及 Gemini 的 `usageMetadata`；不能把 DeepSeek API 文档字段直接当作账号登录返回字段。
- [ ] 检查缓存读取/写入字段、输入输出与思考 token、流式累计事件和重试替换规则。字段未提供应显示未知或不完整，只有明确返回零才表示零；单轮与总量按同一口径核对，不重复累计。
- [ ] 如证实存在返回字段差异，在现有“提供方 + 协议”适配层补齐映射和脱敏回归样本，不为每个模型重复建立适配器；服务端未返回的数据不伪造成实测值。
- [ ] 实测 Gemini 冷切换、热切换、后台刷新、切换账号、退出登录及网络失败，区分认证、目录请求与 UI 等待时间，验证热切换可复用目录且失败原因可见。

完成标准：三类来源均有脱敏样本、预期统计和界面核对记录；DeepSeek 单轮缺失能定位到具体原因并修复可修复的链路，未提供的数据有明确说明；Gemini 有真实账号耗时记录。需要可用测试账号或经用户脱敏的事件样本，当前不将此项标记为通过。

### 11.3 阶段 4：聚合 DSH 官方与社区插件市场

目标是在现有插件页面提供统一目录，聚合 DSH 官方来源与[社区 Plugin Hub](https://dsh-plugin.org/zh/plugins/dshplugin/dsh-plugin-hub)。该 Hub 是社区维护项目，不能标为 DeepSeek 官方。此前的源码调研不代表已经安装或完成集成。

- [ ] 确认社区目录接口、数据使用条件、字段与版本规则，以及对当前 DSH 版本的支持；先确定稳定数据源，再接入目录。
- [ ] 定义来源和插件的稳定标识、作者、版本、许可证、兼容状态及安装描述；按来源记录官方/社区身份与核验依据，处理同名插件。
- [ ] 在现有页面加入统一搜索、来源筛选、详情、兼容提示及已安装状态；目录聚合与已安装状态共用现有插件管理能力。
- [ ] 实现目录缓存、分页或索引、并发请求合并，以及单一来源失败隔离；离线与过期缓存状态对用户可见。
- [ ] 校验结构化安装描述，通过现有桌面 profile/bundle 安装生命周期完成安装、更新、移除与激活；不执行目录返回的任意完整 shell 命令，也不嵌入另一套安装器。
- [ ] 定义更新版本选择、失败恢复、重启/HMR 提示和配置归属；保留用户凭据及无关配置，卸载只清理该插件拥有的资源。

完成标准：官方与社区来源可搜索筛选，安装、更新、移除及重启后的状态一致；来源故障不阻断另一来源，失败安装可恢复，离线信息明确，来源标识无混淆。为安装生命周期提供针对性测试，并对界面变更补充浏览器验证；涉及会话行为时补充对应录制回放，不安排安装包验收。

### 11.4 阶段 5：Codex 官方目录与分层兼容

目标是接入 [OpenAI 插件仓库](https://github.com/openai/plugins)的目录，再按能力逐步适配。目录可见不代表可在 DSH 内执行；所有兼容结论须有实际样本验证。

- [ ] 先核对 `.agents/plugins/marketplace.json` 与 `.agents/plugins/api_marketplace.json` 的用途和访问条件，解析 `.codex-plugin/plugin.json`，支持来源与插件标识去重、固定版本以及更新检查。
- [ ] 第一批交付目录浏览、详情与逐项兼容标识，区分可用、部分可用、待适配与不支持；混合能力插件不能因部分组件可安装而显示为完全兼容。
- [ ] 第二批适配 Skills：检查资源路径、引用文件及工具依赖，记录安装文件归属，验证加载、更新与卸载清理。
- [ ] 第二批适配 MCP：复用 DSH 现有传输、配置和凭据管理能力，逐项验证 `.mcp.json` 所需传输及认证；不支持的 OAuth 或传输方式明确标识。
- [ ] 第三批适配 Hooks：复用现有 [Codex Hooks 桥接](../packages/experimental/hooks-codex/README.zh.md)支持的子集，验证放行、拒绝、取消与卸载行为；超出子集的能力保留待适配状态。
- [ ] 单独评估 agents、commands 等声明；依赖 OpenAI 账号的 `.app.json` 连接器和专有应用界面不能仅凭 manifest 在 DSH 激活，应标为不支持或待适配。
- [ ] 为转换后的文件、服务配置与钩子建立安装归属和冲突处理，保证更新/卸载保留无关资源及用户凭据，并覆盖损坏清单、路径越界、部分失败和版本变化。

完成标准：每种宣称兼容的能力均有可复现样本、针对性测试及安装/更新/卸载记录；不支持的组件不被静默跳过，部分兼容状态可见。先完成阶段 4 的统一目录与安装状态管理，再推进本阶段；不承诺所有 Codex 插件直接兼容。
