# @deepseek-ai/dsh-pet

English | [中文](README.zh.md)

## Summary

Built-in Studio Pet Host module: folds live Session events into one pet snapshot served on the `pet` Remote. The snapshot carries one aggregated character state, a per-Session view, pending approvals, running jobs, the "show desktop pet" flag, and the shared pet settings. It carries no message bodies, tool arguments, or credentials. The module never answers approvals; Clients answer them through the existing approval flow.

<a id="use-this-package"></a>
## Use this package

The web-app bundle mounts this service in the Web and Desktop profiles next to the [ui-pet](../../client/ui-pet/README.md) Client plugin. Clients call `pet.watch()` for a stream of complete `PetSnapshot` frames and `pet.getSnapshot()` for one read. `pet.setVisible(boolean)` toggles every pet surface without stopping the fold and writes the `visible` field of this entry through the [settings](../../settings/settings/README.md) service, so the value survives Host restarts; without Settings or a profile entry it lasts for the Host lifetime. `pet.pin(sessionId | null)` chooses the Session the bubble follows. `pet.acknowledge(sessionId)` ends a `SUCCESS` or `ERROR` hold once the user saw the result. `pet.pack()` returns the pack to render instead of the built-in one (see [Pet packs](#pet-packs)). All methods are owner-only under the default remote-access policy.

The volatile Config fields are the shared pet settings. The ui-pet settings page edits them through the generic settings form of the `pet` entry, and the module applies them on `loader/volatile-update` without remounting:

| Field | Default | Effect |
| --- | --- | --- |
| `visible` | `true` | "Show desktop pet"; hiding keeps the fold and the stream running |
| `restrictTools` | `false` | When on, approvals of tools in `restrictedTools` carry `restrictedInPet: true` and the pet points to the main window |
| `restrictedTools` | `[]` | Tool names routed to the main window |
| `notifyWaiting` / `notifySuccess` / `notifyError` | `true` | System notification categories, published as `snapshot.settings.notify`; each device still opts in |

<a id="pet-packs"></a>

### Pet packs

A pet pack is a directory, not an npm plugin: `pet.json` (format version 2), `lines.json` (zh/en lines by trigger), `assets/`, and `LICENSE`. The built-in pack `whaletail-maid@1.0.0` lives in `packs/whaletail-maid` and is exported as `@deepseek-ai/dsh-pet/packs/*`; ui-pet bundles its frames. `@deepseek-ai/dsh-pet/pack` is the pure, browser-safe parser both sides use: `parsePetPack` checks the format version, id and version, `engines` (caret ranges against pet runtime 1.0.0 and pet API 1), the renderer, the canvas, the frame rate, known animation slots, the required slots (`idle`, `thinking`, `working`, `waiting`, `success`, `error`, `dragging`, each with frames or a `ref`), pack-relative `.webp` / `.png` paths without `..`, reference targets and cycles, and the persona block. It returns every problem at once. `resolvePetClip` follows `ref` and the slot fallback chain down to `idle`. This runtime renders the `frames` renderer only; `spritesheet`, Spine, and Live2D packs are rejected.

The built-in character and its media come from [PC2005-cloud/dsh-pet](https://github.com/PC2005-cloud/dsh-pet) by PC2005-cloud. Its code is MIT; its assets are for non-commercial use only, and derivative works must credit <https://github.com/PC2005-cloud/dsh-pet> wherever they are introduced, shown, or distributed. [UPSTREAM_ASSET_TERMS.md](packs/whaletail-maid/UPSTREAM_ASSET_TERMS.md) quotes the upstream terms verbatim with the pinned upstream commits; the pack's `pet.json` `license.assets` names these terms.

Lines are local and never generated by a model. `@deepseek-ai/dsh-pet/lines` validates `lines.json` (`parsePetLines`) and picks one line for a list of trigger keys (`pickPetLine`, with the random source supplied by the caller). `@deepseek-ai/dsh-pet/time-context` reads the local time of day, workday or weekend, and the surrounding festival (Gregorian dates, lunar dates computed with the built-in `Intl` Chinese calendar, and fixed school-break windows; statutory make-up workdays are not modelled), and `petMomentTriggers` turns that moment into `festival.<id>.<phase>`, `festival.<id>`, and `greet.<slot>` keys. The built-in pack has greetings for every slot and a line for every festival. `pet.pack()` offers the validated table named by `persona.lines` as `lines`; a development pack whose table is missing or invalid is skipped. Both modules are browser-safe and adapted from PC2005-cloud/dsh-pet (see [NOTICE](NOTICE)).

For pack development, `DSH_PET_DEV=1` with `DSH_PET_DEV_PACKS=<dir>` makes `pet.pack()` offer the first valid pack among the subdirectories of `<dir>` (sorted by name), unsigned and marked `dev: true`, with its frames as data URLs (at most 4 MiB per image and 30 MiB per pack). Skipped directories come back in `problems` with their reasons. The directory is read once per Host lifetime. Without the switch, `pet.pack()` offers built-in media when `webServer` is available; otherwise it returns `{ pack: null, problems: [] }` and Clients keep the embedded fallback. Signed packs from studio-cloud are not loaded yet.

<a id="understand-the-implementation"></a>
## Understand the implementation

<details>
<summary>Implementation internals — click to expand</summary>

`PetService` is a `TypertRemoteService` registered at the Host root, so its `session/event` and `session/disposed` listeners see every Session. `PetReducer` is a pure incremental fold:

- `turn/start` sets `THINKING`; `tool/call` sets `WORKING` with an activity classified from the tool name; `tool/result` returns to `THINKING` once no tool is open.
- `turn/end` maps `completed` and `max-tokens` to `SUCCESS`, `error` to `ERROR`, and every other reason to `IDLE`. Results hold for `successHoldMs` / `errorHoldMs`; a timer re-emits when a hold ends.
- With `holdCompletionsWhileBusy` (on by default), a successful result waits while subagent descendants of the Session (children linked by the header `parentSession` with `origin: 'subagent'`, and their children) still run a turn or own an unsettled job. The Session reads `WORKING` meanwhile, and the result settles, with its notification, once they have been quiet for `completionQuietMs` (1500 ms by default). Jobs of the Session itself, such as a dev server, and errors are not held; forks are not descendants.
- Goal rounds announce only the final result. `goal/change` and goal-attributed `user/message` events are read structurally, without importing dsh-goal: a successful round of a goal that still expects rounds reads as `IDLE` with no unseen result; a round that completes the goal reads as `SUCCESS`; a goal blocked during a round, or by the round limit between rounds, reads as `ERROR`. Pausing or clearing a goal between rounds stays quiet.
- `approval/asked` and `approval/decided` (audit events written by user-approval) track pending approvals, including those of subagent Sessions that are otherwise untracked. Any pending approval makes the character `WAITING`.
- Every snapshot carries `moment`, the Host-local time of day, day kind, and festival (`@deepseek-ai/dsh-pet/time-context`); the expiry timer also fires at the next slot boundary so the moment stays current without events.
- `todo/write` gives progress (`current` is the last in-progress item), `session/title` gives the title, and `job/registered` / `job/settled` list running jobs.

Character priority is `WAITING > ERROR > SUCCESS > WORKING > THINKING > IDLE`. A pinned Session wins focus unless `waitingPreempts` lets a `WAITING` Session take it. `watch()` coalesces changes inside `snapshotDebounceMs`. A fold failure is logged and never reaches the Session append path.

</details>

## Known Limitations and Deferred Work

<a id="known-limitations-and-deferred-work"></a>

- **MVP scope** — `TALKING`, compaction and retry states are not implemented. Settings beyond visibility, tool restriction, and notification categories (bubble, persona, hotkeys, updates) are not implemented.
- **Packs** — development packs use the `frames` renderer; built-in media also supports video and sprite clips; no signed studio-cloud packs, content packs, outfits, scripts, or sounds. `lines.json` is shipped and checked by tests, and snapshots carry the `moment` that selects greeting and festival lines; ui-pet speaks those greeting and festival lines, while the task, approval, and idle triggers are not spoken yet.
- **No Host-side approval decision** — deciding from the Host would need user-approval to cancel forwarded Client requests; Clients answer instead.

When `webServer` is available, `pet.pack()` offers the built-in media alongside its fallback frame manifest. `/pet-motion` serves only allowlisted shipped media, supports GET, HEAD, and a single byte range, and removes its route with the owning plugin. Twenty-nine transparent VP9 clips ship: 16 preserve all 3,444 frames imported through dsh-dafeiyu, and thirteen are cut directly from the pinned dsh-pet webm files (three click responses, a look-around that ends facing the other way, three walking clips, and six balance tiers; for walks whose feet show one direction the importer records the travel per frame measured from the foot contacts, so the Client moves the pet with its steps); fourteen generated interaction sheets contain 666 actual frames at per-action 6–10 fps, including four replacements and ten additional sets. Sprite metadata supports a zero-based `startFrame` plus a playback frame count, so sleep and travel entry/loop/exit clips share one atlas URL. Content hashes version media URLs to prevent stale browser caches after an asset update. Their source and encoding records live in `packs/whaletail-maid/motion.json`, which the Host validates with `./motion` before serving; each import tool owns its own clips, and the categories there drive the Client's weighted chain and menu, while its event tiers (balance, work status, whisper) and click areas tell the Client which clips an event or a click on the head, body, or tail plays; `MOTION_LICENSE.txt` keeps the upstream MIT text, which covers code, and the asset terms are described in [Pet packs](#pet-packs). A valid development pack takes precedence.
