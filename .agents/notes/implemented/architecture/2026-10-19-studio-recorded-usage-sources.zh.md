# Agent Note: Studio 已记录用量的来源标识

Status: implemented

[English](2026-10-19-studio-recorded-usage-sources.md) | 中文

## 问题

聊天、个人中心及同步历史可能通过不同窗口或分支副本观测到同一个提供方请求。内容相同不能区分复制的请求与独立但完全相同的请求。分支若在其父会话的种子标记之前截断，声明的直接父会话也无法识别不可获取的祖先。

## 决策

Token-meter 管理归一化后的持久结算记录，扩展[投影用量决策](2026-07-29-projected-token-usage-and-request-context.zh.md)。尝试的首次结算位置是其在原始 Session 内的稳定标识；后续结算替换样本，重试则开始另一尝试。失败调用已记录的用量计入消耗，不估算缺失调用，也不修改 Agent 执行和上下文测量。

全局统计按原始 Session ID 及事件位置去重。已知父会话日志或持久来源区间确定这些标识。祖先缺失及相互矛盾的副本产生明确的部分统计；消息内容、时间戳及种子标记不用于确定标识。提供方精确总量独立于可选缓存明细和提供方余额。

单会话展示包含完整继承历史，与聊天一致。全局总量、模型及日历分桶对原始请求只计一次，复制的工具活动不再贡献。因此不能通过相加展示的 Session 行重建全局总量。

Studio 会话清单使用 `dsh-session-2` 保留来源区间，不修改官方 Session 文件。新版客户端接受旧清单，但旧版 Studio 客户端拒绝新清单。[升级指南](../../../../docs/upgrade-guide/v0.2.1-rc.2/studio-usage-sources/guide.zh.md) 管理设备迁移说明。其他 Session 格式代际的事件位置不可获取，除非兼容导出提供这些位置。

## 考虑过的替代方案

**对完整轮次取哈希，或比较消息和时间戳。** 独立但完全相同的请求会被合并，脱敏或不完整观测则可能使复制请求无法匹配。内容比较可以发现已确定标识的观测相互矛盾，但不能确定标识。

**将所有继承事件归给声明的直接父会话。** 缺失的父日志本身可能包含继承请求。即使没有种子标记也无法判定，因为复制前缀可能在标记之前结束。

**对每个展示的 Session 总量去重。** 子会话行将与其聊天消耗不一致。全局汇总与单会话披露回答不同问题，分别保留总量。

## 影响

祖先不可获取时，已知全局消耗可能减少，而不编造标识或零值。已记录用量不是提供方账单。可见摘要从 Host 刷新，隐藏摘要不主动扫描历史，显式重新打开时刷新。这不会新增后台提供方轮询或模型上下文。

现有投影用量说明保持活跃，继续管理请求统计与上下文占用语义，不管理跨 Session 标识。没有替代已有决策。Loader 组合与 JSONL 冷读取测试通过所属包的期望输出固定重试、日历、分支、聊天展示和释放行为。
