# DSH Studio 云端服务设计

状态：功能范围已确认，独立服务基础实现已建立；本文保留目标设计，实际能力及尚未实现的部分以 [README.md](README.md) 为准。不修改任何客户端源码，不进行客户端与服务端对接。

## 一、已确认范围

| 项目 | 确定需求 |
| --- | --- |
| 使用对象 | 个人账号，首期不做组织和团队共享空间 |
| 账号开通 | 管理员创建或邀请，不开放注册 |
| 登录 | 账号密码登录；绑定并验证邮箱后也可用邮箱和密码登录 |
| 找回 | 通过已验证的绑定邮箱重置密码 |
| 首期同步 | 个人资料、偏好、项目、对话记录、插件数据 |
| 加密 | 支持可选端到端加密，不强制开启 |
| 访问协议 | 支持 HTTP 内网连接，也支持 HTTPS |
| 部署 | Docker 部署 |
| 管理 | 提供独立管理界面 |
| 存储 | 可配置 S3 兼容存储，包括 MinIO |
| 策略 | 可配置容量额度、删除保留期、备份保留期等 |

DSH Studio 登录负责个人云端身份与同步，API Key、DeepSeek 官方登录等继续负责模型访问。Studio 账号不自动获得模型额度，也不接管现有模型凭据。

## 二、模块边界

- 模块目录为 `services/studio-cloud/`，独立服务、依赖、数据库、迁移、配置和 Docker 部署文件；所有新增文件限制在该目录。
- 管理界面的源码和构建产物也属于本模块，不使用或修改现有桌面/Web 客户端页面。
- 不改客户端、现有同步包、根目录依赖和锁文件；不连接或迁移客户端本地数据库。
- 仓库已有设备凭据式 `packages/sync/sync-server`。新服务不直接改造它，不自动继承其身份或已有数据；旧协议兼容及迁移另行安排。
- 后续独立用户登录入口、客户端接入与加密操作界面属于其他任务；本服务提供所需接口与加密数据存储能力。

## 三、账号与邮箱

### 开通及登录

- 管理员可创建账号，用户使用临时密码后需设置新密码；不向管理员展示已有密码。
- 管理员也可发出邀请链接或邮件。邀请具有有效期、使用次数限制和撤销能力；接受邀请时设置账号和密码。
- 接受邀请不是开放注册；没有有效邀请或管理员创建的账号不能自行开通。
- 用户名及已验证邮箱分别保持唯一，并避免用户名与邮箱登录标识的歧义；邮箱登录仍需要密码，首期不增加邮箱验证码登录。
- 支持查看登录设备、退出当前/其他设备、管理员禁用账号及撤销登录会话。

### 邮箱绑定与找回

- 绑定邮箱需要登录状态、密码复核和邮件验证；修改邮箱需重新验证，不通过未经验证的地址登录或找回。
- 找回密码使用短期、一次性的邮件链接；令牌仅保存哈希，发送结果不暴露邮箱是否存在。
- 重置密码后撤销既有登录会话；管理员重置密码同样执行撤销。
- 未绑定邮箱的账号不提供邮箱自助找回，由管理员协助处理；邀请、验证和找回邮件使用可配置 SMTP。
- 账号密码找回与端到端加密密钥恢复相互独立，重置密码不会自动解密历史数据。

## 四、同步数据

| 数据 | 范围 |
| --- | --- |
| 个人资料 | 昵称、头像引用等；登录邮箱和账号状态由账号接口单独管理 |
| 偏好 | 明确允许同步的界面与个人设置 |
| 项目 | 名称、基本信息、会话关联及删除状态，不默认上传本地整个代码目录 |
| 对话 | 会话列表、消息及允许上传的事件和结果；不执行工具或接管正在运行的智能体 |
| 插件数据 | 插件标识/版本、启用状态、允许同步的配置与插件个人数据，按插件及数据版本隔离 |

插件同步数据是存储和恢复记录，不是插件安装或云端执行。首期不上传插件可执行文件；未来恢复插件所需安装动作由客户端接入任务决定。插件 API Key、OAuth 令牌、密码、环境变量、本地路径等不进入同步配置；插件必须声明可同步字段与数据格式，未知或不支持版本应明确返回状态。

对话和插件可能包含较大资源，对象存储可保存这些数据引用的允许上传的资源；具体允许的文件类型及大小需在实现前确定。个人记忆、文件盘和团队协作不自动扩展为首期能力。

## 五、可选端到端加密

建议每个个人账号选择普通同步或端到端加密同步，账号状态记录加密模式和密钥版本；首期不支持两种模式的无感自动切换。

| 项目 | 普通同步 | 端到端加密同步 |
| --- | --- | --- |
| 同步内容 | 服务端可读取，使用存储加密保护 | 由未来接入方加密后上传，服务端保存密文 |
| 账号登录信息 | 服务端管理 | 同样由服务端管理，不隐藏用户名或登录邮箱 |
| 内容元信息 | 服务端可读取 | 仅保留必要对象 ID、类型、版本、关联、大小和同步时间；名称等放在密文中 |
| 管理界面 | 首期默认只展示同步元信息，不提供正文浏览 | 不能查看明文、解密或代替用户恢复数据密钥 |
| 数据校验 | 校验允许字段和内容版本 | 校验加密信封、大小、版本、权限及关联，不能验证密文内部字段 |

端到端加密覆盖个人资料中的同步内容、偏好、项目、对话和插件数据；账号标识、登录邮箱、设备及用量等服务运行元信息不在此范围。所有同步内容和资源必须使用经过审查的标准认证加密方案，避免设计自有密码算法。

建议使用随机数据密钥、设备密钥授权及用户保管的恢复密钥。服务端只保存封装后的密钥材料，不能持有可直接解密的用户主密钥；恢复密钥不上传明文。登录密码和数据加密主密钥分离，普通密码重置不破坏或绕过加密。

新设备需要已有设备授权或恢复密钥才能解密。丢失所有授权设备及恢复密钥时，管理员也无法恢复历史明文；可重建加密空间但必须明确处理旧数据。撤销设备可以停止后续下载，无法撤回它已经获得的数据或密钥；密钥轮换按版本处理后续数据。

普通模式与加密模式转换需要专门的数据重写流程；服务端不能自行解密迁移。首次启用建议只针对空的同步空间，已有数据迁移另行确定。服务端可先通过加密协议测试样本验证存储能力，不需要修改客户端来完成本轮开发。

## 六、HTTP 与登录安全

- 内网部署允许通过 HTTP 完成登录和同步，服务端不强制跳转 HTTPS；公网建议通过反向代理提供 HTTPS。外部访问地址、代理信任及协议策略均可配置。
- HTTP 上的密码、令牌和未加密内容没有传输加密保护；端到端加密只保护同步内容，不能替代登录链路的 HTTPS。
- 管理界面支持同源 HTTP 内网使用，也支持 HTTPS。登录 Cookie 使用 HttpOnly 和适当的 SameSite 策略；HTTPS 下启用 Secure，显式启用 HTTP 部署时调整为可用配置，同时保留 CSRF、来源检查和会话过期控制。
- 桌面接口使用可撤销的短期访问令牌与轮换刷新令牌；设备会话、用户禁用或密码重置后，访问和刷新权限均需失效。网页登录会话与桌面令牌分开管理。
- 密码采用 Argon2id 哈希；登录、邀请、验证邮件和找回接口限流。日志不记录密码、令牌、邮件链接或对话正文。
- 所有对象及批量、下载接口都从登录身份确定用户所有权；不能通过传入其他用户 ID 越权。

## 七、同步协议

采用 HTTP 批量上传和游标增量下载，协议独立版本化；普通载荷与加密载荷共用身份、对象版本、冲突和容量规则。

1. 上传携带设备会话、幂等请求 ID、对象 ID、基础版本及载荷版本；加密对象额外携带密钥版本和加密信封。
2. 一个批次在数据库事务内全部提交或全部失败。重复请求且内容相同返回原结果；请求 ID 相同但内容不同返回冲突。
3. 服务端分配与事务提交顺序一致的用户增量序号，下载通过不透明游标分页，避免并发写入导致漏数据。
4. 可变对象使用版本比较更新；并发冲突保留可恢复的双方版本，不静默覆盖。密文冲突由未来接入方解密处理，服务端不合并密文。
5. 对话事件按稳定事件 ID 去重、按连续序号追加；重复 ID 内容不同、顺序缺口或分叉明确返回冲突。
6. 删除生成参与版本比较的删除标记。保留期内可恢复；旧设备不得直接覆盖删除标记导致数据复活。
7. 删除标记和增量日志独立设置保留期；游标过期后要求全量同步，使用一致性快照及对应游标继续增量下载。
8. 禁用账号、撤销设备、越权或超额时不部分写入。上传响应丢失后可使用原请求 ID 重试。

对于对象存储资源，先暂存上传并计入预留额度，再确认大小、所有权与内容校验后发布数据库引用；处理数据库与对象存储不能跨系统原子提交的问题，失败资源须可清理，不能发布未完成上传的引用。

## 八、管理界面

管理界面由新服务单独提供，管理员登录与个人账号角色分离。建议包含以下页面：

| 页面 | 功能 |
| --- | --- |
| 概览 | 用户数、设备数、存储使用量、同步失败和最近备份 |
| 用户 | 创建账号、禁用/启用、密码重置、额度调整、设备撤销 |
| 邀请 | 创建/发送、到期时间、使用状态、撤销 |
| 用户数据 | 查看项目/会话/插件数据的元信息、占用和删除状态，不默认浏览正文 |
| 存储设置 | S3/MinIO 配置、连接测试、存储用量和迁移状态 |
| 邮件设置 | SMTP、发件人、邀请/绑定/找回邮件测试 |
| 策略设置 | 默认及个人额度、删除保留期、增量保留期、备份周期和保留期 |
| 备份恢复 | 发起备份、查看记录、校验和恢复；恢复前进入维护状态并确认目标 |
| 审计 | 账号、邀请、配置修改、数据清理和恢复等管理操作 |

首个管理员通过部署时的一次性初始化方式创建，不暴露开放的管理员注册接口。存储、SMTP 等密钥加密保管，不在设置查询中返回原值；保护密钥由部署环境提供，不随数据库明文备份。

## 九、存储、额度和保留策略

支持标准 S3 兼容接口及 MinIO，可配置 endpoint、region、bucket、访问凭据、路径前缀、寻址方式和内部 HTTP/HTTPS 连接。切换存储目标不直接切断旧数据访问，必须迁移或保留原目标映射；迁移完成后才清理旧位置。

PostgreSQL 保存账号、元信息、同步版本和增量日志；对象存储保存允许上传的大对象及备份文件。MinIO 可作为可选 Docker Compose 服务，也可连接现有外部 S3/MinIO。

- 容量：提供默认个人额度和管理员单独覆盖，按用户实际持久化的同步载荷及资源字节计量；密文按密文大小计量，不信任接入方申报的明文大小。计量口径及可恢复历史版本占用在管理界面展示。
- 超额：禁止新增或扩大占用的写入；仍允许登录、下载、删除及不会增加占用的必要状态操作。并发上传需原子预留容量，防止绕过额度。
- 删除保留期：软删除后保留恢复窗口，期满清理正文/密文和对象资源；删除标记保留时间单独管理，防止旧设备复活数据。
- 备份：配置周期、保留期限、保留份数和目标。备份容量单独计量并设置服务级上限，避免与用户同步额度混淆。
- 保留策略修改：说明对已有数据的生效方式；缩短期限后先显示待清理范围，再由管理员确认清理。
- 备份内的已删除数据随备份到期清理，界面说明其最长残留时间。恢复后重新应用删除记录和保留规则；若恢复点缺少后续删除记录，需明确标识并由管理员核对，不能声称旧备份恢复会自动保留所有后续删除。

备份同时覆盖数据库、对象资源清单、同步版本及封装密钥材料；恢复要验证资源一致性，必要时切换同步代次使旧游标失效。端到端加密备份仍是密文，不包含用户恢复密钥。

## 十、技术与部署建议

建议采用 TypeScript + Node.js + Fastify + PostgreSQL，管理界面作为本模块自带的独立 Web 应用，由服务提供静态资源及管理 API。首期不引入微服务、消息队列或 Redis；清理和备份任务需要数据库任务锁，防止重复执行。

Docker Compose 包含应用、PostgreSQL 和可选 MinIO，使用持久卷和环境配置；HTTPS 反向代理按部署需求选配。数据库迁移、健康检查、备份恢复和初始管理员配置均在本模块维护。

主要数据包括：用户与已验证邮箱、邀请/找回令牌哈希、设备会话、个人设置、项目与对话、插件同步数据、对象资源、同步增量与幂等记录、加密模式与封装密钥、额度、保留策略、备份任务和管理审计。所有个人数据表使用用户所有权约束，防止跨用户关联。

API 按 `/v1/auth`、`/v1/me`、`/v1/sync`、`/v1/plugins`、`/v1/objects`、`/v1/crypto` 和 `/v1/admin` 分组。邀请兑换接口可以未登录调用，但必须持有效邀请；不提供开放注册接口。接口和启动入口在实现前细化，本轮不新增可执行程序。

## 十一、实施顺序与待细化项

1. 账号、邀请、邮箱验证/登录/找回、设备撤销，以及独立管理界面的用户管理。
2. 五类个人数据的同步协议、隔离、版本冲突、删除及插件数据格式。
3. 可选加密信封与密钥授权存储、S3/MinIO、额度及资源上传生命周期。
4. 管理设置、保留策略、备份恢复、Docker 部署与服务端验证。

以上均限定在独立模块。后续客户端的服务地址配置、登录入口、加密和恢复界面、实际上传下载与插件恢复不在本轮实现范围。

还需在实现前细化：插件可同步数据清单及格式、允许上传的资源类型、额度/保留期限默认值，以及加密空间启用和已有数据迁移规则。这些不改变上面已确认的功能范围。

服务端验证重点是账号开通限制、邮箱令牌一次性与过期、权限撤销、跨用户隔离、幂等及并发同步、密文不被解密、HTTP/HTTPS 部署、S3/MinIO 兼容、并发额度限制、过期清理和备份恢复。当前没有实现这些功能，也没有修改客户端进行验证。
